# NOTATKA — 2026-11-17 — ShoppingList (strażnik ceny ujemnej, `continue`)

## Cel sesji

Cena ujemna nie wchodzi na listę: komunikat, powrót do pytania o cenę, produkt NIE dodany.

## Co zrobione

Wszystko wpisane ręcznie, po jednej linii:

1. pusta linia nad `break;` w bloku `TryParse`,
2. `if (price < 0)` — **wewnątrz** bloku `TryParse`, bo tam `price` ma już wartość z `out price`,
3. klamry `{ }` wokół `if`, żeby `break;` został **poza** warunkiem,
4. `Console.WriteLine("Price cannot be negative. Try again:");`,
5. `continue;` na końcu bloku `if`.

Efekt w pliku:

```csharp
if (decimal.TryParse(priceText, System.Globalization.CultureInfo.InvariantCulture, out price))
{
    if (price < 0)
    {
        Console.WriteLine("Price cannot be negative. Try again:");
        continue;
    }
    break;
}
Console.WriteLine("That is not a number. Try again:");
```

## Nowe pojęcie tej sesji

- **`continue`** — wróć na początek **tej samej** pętli (okrążenie się nie liczy), naprzeciw znanego `break` = wyjdź z pętli. Tu `continue` wraca do pytania o cenę, więc `products.Add` i `total` w ogóle nie widzą ceny `-5`.
- **Dlaczego `if` stoi właśnie tam** — `decimal price;` to puste pudełko; wartość wkłada dopiero udane `TryParse` (`out price`). Wyżej nie ma czego porównywać, a poza blokiem sprawdzałbyś `price` także wtedy, gdy wpisano `abc`.

## Poprawki i pułapki tej sesji

- **`if` bez klamer wchłania następną linię** — po wpisaniu samego `if (price <0)` stojące pod nim `break;` zostało jego ciałem, czyli „przerwij, gdy cena JEST ujemna". Build był zielony, bo to poprawna składnia. Klamry rozdzieliły warunek od `break`.
- **`(true)` w obu pętlach** — user poprawił asystenta: oba `while` mają `(true)` w nawiasie, więc żadna nie kończy się sama; wyjście tylko przez `break`.
- **Literówka w napisie: `agin` zamiast `again`** — build milczał; wyszło z porównania z docelowym tekstem. Wnętrza cudzysłowu kompilator nie sprawdza.
- **Zmiana w edytorze ≠ zmiana w pliku** — pierwsza pusta linia nad `break;` żyła tylko w VS do `Ctrl+S`.

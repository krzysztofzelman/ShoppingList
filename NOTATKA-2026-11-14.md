## Kod — stan pliku na koniec dnia

```csharp
List<string> products = new List<string>();
    decimal total = 0;
while (true)
{
    Console.WriteLine("Product name (or 'end'");
    string name = Console.ReadLine() ?? "" ;

    if (name == "end")
    {
        break;
    }
    Console.WriteLine("Price");
    decimal price = decimal.Parse(Console.ReadLine());

    products.Add($"{name} - {price}");
    total = total + price;
}
Console.WriteLine();

foreach (string product in products)
{
    Console.WriteLine(product);
}
Console.WriteLine($"Total: {total}");
```

## Bloki, z których powstał program

1. dwie zmienne: `List<string> products` (pusta lista) + `decimal total = 0`;
2. pętla `while (true)` z pytaniem o nazwę i wyjściem przez `break` na `end`;
3. pytanie o cenę: tekst z `Console.ReadLine()` → liczba przez `decimal.Parse`;
4. `products.Add($"{name} - {price}")` + `total = total + price`;
5. po pętli: pusta linia, `foreach` po liście, `Total: {total}`.

## Błędy tej sesji — co pokazały

| Objaw | Przyczyna | Reguła |
|---|---|---|
| `CS0103 nazwa „price” nie istnieje` (2×) | pytanie o cenę i `decimal price` stały **w środku klamry `if`** | zmienna żyje tylko do klamry, w której powstała — deklaracja na poziomie pętli, nie `if` |
| `CS0103 nazwa „product” nie istnieje` + „prawdopodobnie omyłkowo pusta instrukcja” | `foreach (string product in products);` — średnik zamknął pętlę bez ciała | średnik po `foreach (...)`/`for (...)`/`if (...)` = konstrukcja bez ciała |
| `CS8600` / `CS8604` | `Console.ReadLine()` może oddać `null` | `?? ""` („jeśli null, weź pusty napis”) zamyka oba ostrzeżenia |
| brak koncepcji sterowania pętlą | `break` musi stać **zaraz po sprawdzeniu `end`**, a pytanie o cenę **po** klamrze `if` | kolejność w ciele: sprawdź wyjście → dopiero obsłuż produkt |

## Czego NIE udało się domknąć

**Zrozumienie kodu.** Build przechodzi (meldunek usera), ale po programie zostało: „przechodzi ale chuj rozumiem z tego kodu, sam bym nie napisał”. Kod powstał z bloków asystenta, więc brakuje **mapy programu**, nie składni.

Stan na koniec dnia:
- przebieg programu (`Milk` / `4.50` / `end`) **niepotwierdzony** w tej sesji;
- rozbiór linii po linii **odłożony przez usera na następną sesję** („jutro to ogarniemy rozbierzemy wszystkie linie”);
- dwie kosmetyczne literówki w napisach: `"Product name (or 'end'"` (brak `)` i `:`) oraz `"Price"` bez `:` — kompilator ich nie widzi, program działa.

## Plan następnej sesji

1. **Rozbiór wszystkich linii** tego pliku — po **2 linie na wiadomość**: tłumaczenie po polsku + jedno pytanie o tę linię do usera; brak odpowiedzi = STOP i wracamy do tego samego kawałka inaczej.
2. Trzy miejsca, które muszą być w głowie: `price` w środku pętli (nowa cena na każdy produkt), `products.Add` (lista rośnie o 1), `foreach` po pętli (czyta gotową listę).
3. Dopiero potem jedna **własna** zmiana w programie (np. wypisanie liczby pozycji przez `products.Count` — właściwość bez nawiasów).
